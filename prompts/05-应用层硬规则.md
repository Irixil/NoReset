# 应用层硬规则 · 当前 MVP 实现状态

以下边界由当前后端执行：

- 模型没有数据库写权限，只能返回草稿。
- Schema 失败、来源缺失、危险升级失败或输出含禁行动时，拒绝写入当前方案。
- 不允许自动变更用药方案。记录可以被核对为准确，但不代表处方或治疗获批；若未来开放方案状态迁移，仍须医生/药师直接证据和真实确认。
- 原始文字不可被模型覆盖；修订新增记录，旧原文留在历史。没有提供删除 API，也未实现附件上传。
- 急性危险标记不得被家庭“确认”按钮降级或隐藏。
- 成功整理保存 trace_id、provider、配置模型 ID、提示词版本与哈希、输入哈希、Schema、耗时、草稿及安全补标结果；失败保存异常类别、固定脱敏原因、原文与输入哈希、本地规则结果和审计。模型 ID 是请求配置值，不代表供应商内部权重快照；真实模型尚未调用验证。活动版本来自 prompts/VERSION。
- 单条事件整理链路的摘要及证据保留完整原文，禁止部分摘录改动剂量、否定、条件或主体；该链路的追问继续只用固定模板。连续会话使用独立的 `conversation-intake-v3` 合同：模型只能生成带原话证据的简短回应和一个候选问题，经过问题范围、重复和医疗建议门限后才可显示。输入来源标签不是身份核验，冲突引用校验也不代表已经证明语义冲突。
- 新规则重新扫描旧记录但不清除旧危险提醒，历史原始证据和旧交接材料不回写。前端同时看 local_safety 与草稿升级字段。
- AI 调用前先提交原文存储和本地规则结果；失败不生成医学结论，不冒充整理成功。
- 前端展示“已保存”前必须收到后端成功响应；失败、超时和部分成功必须可见。
