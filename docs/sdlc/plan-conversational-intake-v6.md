# 病历不归零·内测版实施方案：自然对话引导

> 依据 `intent-conversational-intake-v2.md` 与 `spec-conversational-intake-v6.md`，完整取代 `plan-conversational-intake-v5.md`。继续使用现有前后端、DeepSeek、本机加密仓库和安全扫描，不新增框架或服务。

## 1. 最小技术路线

每一轮仍只调用一次模型。模型同时完成理解用户意图、抽取有证据的事实、给出简短回应、判断是否需要继续和提出一个候选问题。后端确定性控制器验证后才返回前端；模型不能直接决定显示、停止或紧急提醒。

不建立多智能体、疾病知识库或复杂流程引擎。复用现有 OpenAI-compatible DeepSeek 客户端、Python 标准库正则、本机会话仓库和浏览器原生能力。

## 2. 模型合同

新增独立 `conversation-intake-v3` 合同。模型返回固定 JSON：用户意图、是否增加事实、回应及证据回合、四类事实状态及证据、建议动作、问题主题、重要级别和一个候选问题。

提示词明确：只能复述已有事实和询问可观察经过；不能诊断、猜病名、推荐检查、建议就医、治疗或改药。输入包含老人回合和控制器中最近问题，帮助模型判断最新一句是在回答、纠正还是投诉没听懂。

## 3. 控制器和校验

1. 严格校验 JSON 字段、枚举、长度、真实回合编号和每轮一个问号。
2. 用明显事实规则补足模型漏看的部位感受、开始变化和生活影响，只把明确出现的原话升级为 `known`，不推断病因。
3. 保存每主题提问次数和最近问题文本。通常一问；答非所问或明确纠偏时允许同主题第二问；相同问题不得重复。
4. 核心缺口优先于可选细节；信息足够、两轮无新事实、明确结束、主题关闭、六问上限或危险命中时停止。
5. 禁用内容扫描同时在后端和前端执行。普通模型输出命中诊断、检查、就医、治疗、药物或剂量内容时整条丢弃并使用固定安全文案。
6. 本地危险扫描先执行；命中时不调用模型，继续使用固定提醒。

## 4. 前端会话状态

扩展现有控制器对象，增加 `question_counts` 和 `asked_questions`；旧会话缺少新字段时按已问主题迁移为一次，不破坏既有数据。

结束文案后的新输入先判断是否为“没听懂”、纠正、继续或补充。属于纠偏时不重置话题状态；真正的新健康描述才重置控制器。原始对话和报告仍属于同一会话。

前端只展示后端已验证回复或两类固定安全文案；原话先保存、失败可恢复、自动报告、编辑历史和音频生命周期保持不变。

## 5. 验证

1. 单元测试覆盖自然回应、一次一问、答非所问后补问、元反馈纠偏、明显事实防重复、完整长回答早停、不知道关闭、两轮无事实、六问上限和危险规则。
2. 对抗测试用伪造模型输出证明诊断、检查、治疗和停药文本被整条阻断；伪造证据编号和缺证据状态被拒绝。
3. 使用明确标注为完全虚构且不对应任何人的合成数据调用真实 DeepSeek，验证自然回应、连续追问、停止和安全拦截；不拿项目所有者页面中的健康原话做外部联调。
4. 运行全部 Python、前端和 TypeScript 检查。
5. 在 5173/18768 真实浏览器复现“伸不直—下不了地—你没听懂”的完整路径，检查回复、报告、刷新恢复、控制台和网络错误。
6. 项目所有者在本地页面亲自验收后，才决定是否更新 README、提交和推送 GitHub。

## 6. 暂不扩大

- 本轮不建立疾病问诊模板，不为具体病种增加追问树。
- 本轮不把临床危险规则扩展为医学分诊；规则覆盖由合格临床人员另行审查。
- 本轮不做实时通话、长期录音、云端健康资料库或自动发布。
