# 病历不归零·内测版实施方案：连续语音引导（草案）

> 依据 `intent-conversational-intake-v2.md` 与 `spec-conversational-intake-v5.md`。本方案取代 `plan-minimal-loop-v4.md` 的逐段整理交互，但保留现有本机加密、媒体识别、来源追溯、照片原件和医生交接能力。

## 1. 总体做法

沿用当前前后端双端口和本地优先架构，不引入新的框架或付费服务。新增“会话、对话回合、滚动报告、完整性状态”四类数据；当前单条 Event 和媒体记录作为底层证据继续使用。

每一轮使用同一次模型请求完成三件事：抽取有证据的事实、判断沟通记录是否足够、提出最多一个候选追问。模型不能直接决定继续；前后端共享的确定性控制器执行停止和安全规则。

## 2. 底层数据

1. 在本地加密仓库增加 Conversation、Turn、ReportDraft 和 ReportVersion。
2. Turn 保存说话人、逐字文字、时间、输入来源、修改版本、关联 Event 和识别媒体编号。
3. ReportDraft 保存当前事实快照、每条事实的 Turn 证据、完整性状态、本人核对状态和覆盖到的最后回合。
4. 每次老人回合先写入 Turn 和原始对话报告，再发起网络请求；请求失败不回滚原话。
5. 成功转写的音频在会话暂停或结束后清理；失败或处理中断的音频保留为待重试。
6. 为现有 Event 增加兼容读取层，不删除或覆盖当前用户数据。

## 3. 对话控制器

1. 使用固定枚举表示 `known / unknown / declined / not_applicable / missing`，以及 `essential / useful / optional`。
2. 保存已问主题、已关闭主题、连续无新事实次数、系统追问次数和用户结束信号。
3. 只有存在新的 `essential` 缺口且所有门槛通过时才放行一个问题。
4. 完整、用户结束、两轮无新事实、主题关闭、六轮上限或危险命中时停止追问。
5. 停止后仍接受老人主动补充，并重新评估同一会话；不自动创建重复报告。
6. 控制器放在可独立测试的纯逻辑模块中，前端和后端不得各写一套不同规则。

## 4. 模型与安全边界

1. 新建独立的会话回合 Schema 和提示词版本，不复用当前单条事件的自由摘要合同。
2. 模型只返回结构化事实、证据回合、覆盖状态、建议动作和一个候选问题。
3. 后端先执行本地危险扫描，再调用模型；危险命中时不让模型自由生成提醒。
4. 对事实来源、问题主题、重复、诊断、病名判断、药物变更、剂量和治疗方案逐项校验。
5. 任何校验失败都丢弃整条模型回复，使用固定安全文案；原始回合和旧报告不受影响。
6. 报告生成使用同一事实快照和来源校验，不接受没有 Turn 证据的内容。

## 5. 接口

1. 新增会话回合接口：接收会话编号、当前回合、本地会话状态和必要的历史证据，返回受约束结果。
2. 请求带版本号和幂等键，重复提交不能增加两次回合或报告版本。
3. 关闭页面不依赖最后一刻网络请求；前端每轮已经保存，页面隐藏事件只写“暂停”状态。
4. 重新进入时先读本地会话，再决定自动续聊或显示隔日二选一。
5. 保留当前事件整理接口供档案和旧数据使用，但新聊天页不再逐段调用它生成摘要卡。

## 6. 前端

1. 把当前语音记录页改为旧原型方向的聊天流：AI 左、老人右、底部固定麦克风和文字备用输入。
2. 麦克风采用一轮一轮的语音聊天；停顿自动结束本轮并进入转写，不再要求点击“保存原录音”。
3. 每个老人气泡可原地修改；修改后生成新 Turn 版本并重新整理报告。
4. AI 回复同时显示文字并使用浏览器系统朗读；朗读失败不阻断文字聊天。
5. 每轮只显示当前状态，不展示摘要卡；报告在档案和可选结束页查看。
6. 同日自动恢复；隔日显示“继续上次记录”和“记录新的情况”两个大按钮。
7. 沿用现有老人端视觉语言，不重新设计一套品牌，也不加入不必要动画。

## 7. 自动报告和退出

1. 本地原始对话报告在保存 Turn 时同步更新，不需要 AI。
2. 模型成功后更新结构化 ReportDraft，并增加可追溯版本。
3. 直接退出时使用最近已保存版本，标记“自动整理·本人未核对”。
4. 回来继续时更新同一个 ReportDraft；手动结束只改变状态，不是生成报告的前置条件。
5. 模型失败时报告至少包含完整原始对话，并明确标记“尚未完成结构整理”。

## 8. 验证顺序

1. 控制器单元测试：完整长回答早停、零碎回答逐步补全、不知道/拒绝关闭主题、重复问题阻断、两轮无新增停止、六轮硬上限、危险立即停止。
2. 安全对抗测试：要求诊断、病名、加减停换药、剂量和治疗方案时，模型输出和报告全部被门限阻断。
3. 数据测试：每轮先保存、刷新恢复、修改保留旧版本、重复请求不重复写入、暂停后清理成功音频、失败音频可重试。
4. 前端合同测试：不出现逐段摘要卡和独立保存录音步骤；同日续聊、隔日二选一、气泡原地修改和固定安全文案可见。
5. 隔离浏览器闭环：连续说话 → AI 自行早停 → 直接关闭 → 重新打开 → 继续同一报告 → 生成医生材料。
6. 使用低价真实模型运行受控样例，只做一次小规模连通和安全门限验证，不自动重试或扩大花费。
7. 项目所有者在本地 5173 页面亲自使用确认后，才准备 GitHub 更新；本方案本身不授权推送或公开部署。

## 9. 旧工作处理

- 保留：本地加密仓库、事件与媒体原件、识别链路、修改历史、报告打印、来源和安全扫描。
- 调整：当前逐段 VoiceTurn、摘要卡编辑和单条 organize 调用改为 Conversation/Turn/ReportDraft。
- 退役：每说一段就出现整理卡、要求手动保存原录音、依靠“最多六轮”而没有完整性控制器的流程。
