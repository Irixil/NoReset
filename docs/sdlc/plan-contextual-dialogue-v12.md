# NoReset·内测版实施方案：理解上下文的健康对话与交接

> 2026-09-30 用户明确纠正的继任版本。仅强化真实语音、切题回应和全流程可用验收；未改变原已接受的隐私、来源、医疗边界和发布范围。原版本留存历史。

## 1. 最小可行路线

保留现有单前端、单后端、DeepSeek、浏览器加密仓库和确定性安全控制器。不建立多智能体，不为每个疾病制作独立问答树，也不引入新的数据库或框架。

每轮仍尽量只调用一次模型。区别是模型输入增加精简健康背景，输出从“四类字段”升级为统一临床采集状态；本地程序继续决定能否显示问题、何时停止和是否触发固定风险提醒。

## 2. 数据结构

新增本机加密 `health_context`：

- 用户确认的既往疾病与时间；
- 手术、外伤、过敏；
- 当前长期用药，只记录名称和用户提供的用法，不给建议；
- 重要检查、测量和日期；
- 过去相似情况；
- 每项来源、确认状态和最后更新时间。

会话状态升级为：

- `clinical_facts`：有证据事实；
- `unknowns`：仍缺失但可能影响交接的信息；
- `contradictions`：相互矛盾的来源；
- `relevant_context_ids`：本轮实际使用的背景；
- `risk_candidates`：规则编号和原话证据；
- `question_history`：问题、目的、是否回答；
- `handoff_readiness`：是否足以形成交接及剩余缺口。

## 3. 模型合同

DeepSeek 每轮返回严格 JSON：

1. 对最新一句的意图和切题回应；解释与支持不得被写成患者事实，回应后可选择不追问；
2. 新增、修正、否认、未知或冲突的结构化事实及证据；
3. 本轮相关的既往背景编号，不得改写背景事实；
4. 风险候选编号和触发证据；
5. 交接完整度、仍缺少的关键事实；
6. 最多一个候选问题及其临床信息目的；
7. 建议追问、仅回应或停止；不能为保持流程而每轮强行追问。

内部可以判断哪些临床方向需要澄清，但对外不得返回疾病猜测或诊疗方案。

## 4. 控制器

- 验证所有事实和风险候选的真实来源。
- 拒绝重复、无关、复合问题和已明确拒答的问题。
- 根据回答情况动态选择问题，不按照固定顺序。
- 八问后只允许仍有明确价值的问题；十二问硬停止并把缺口写入交接材料。
- 后端和前端继续双重阻断诊断、治疗、用药、剂量和具体检查建议。
- 风险候选必须命中临床审核的版本化规则，才能显示对应固定文案。

## 5. 报告生成

模型只产出带来源的结构化事实和优先级，本地渲染器生成老人视图与医生交接视图。报告不直接接受模型自由文本作为医学结论。

医生交接视图采用“当前情况—相关背景—现病经过—风险与待核实事项—原始来源”的顺序，兼容打印和手机展示。所有修改生成新版本。

## 6. 分阶段实现

1. 建立健康背景结构、编辑入口和迁移；旧资料保持不变。
2. 新增 `clinical-intake-v1` 模型合同和确定性校验器。
3. 将现有会话控制器迁移到动态临床采集状态，同时兼容旧会话。
4. 实现风险规则接口和两套固定提醒；先只加载现有已审核规则。
5. 重做报告生成和医生交接视图，保留老人简明视图。
6. 用虚构病例完成离线、真实 DeepSeek 和隔离浏览器验证。
7. 交由合格临床人员审查问题策略、风险规则和交接材料；未审查项继续显示“待验证”。

## 8. 成本和隐私控制

- 每轮一次模型调用，不增加第二个判断模型。
- 只发送精简结构化背景和当前事件相关回合，不发送完整历史库。
- 对话过长时在本机保留全量原话，只向模型发送带来源的已确认事实和最近回合。
- 继续使用现有 DeepSeek/AIHubMix 接入，不新增付费服务。
